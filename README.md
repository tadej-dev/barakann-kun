## 1. サービス概要（※最後に書いてOK）

ロードバイクのバラ完（パーツを個別に選んで組み上げること）を支援するシミュレーターサービスです。

フレーム・コンポーネント・ホイールなどを自由に組み合わせ、価格・重量を可視化することで、初心者から上級者まで安心して理想の1台を設計できる環境を提供します。

ロードバイクユーザーが抱える「この組み合わせで本当に組めるのか？」「完成したらいくらになるのか？」という不安を解消することを目的としています。

---

## 2. このアイデアはどこから生まれたか

ロードバイクを趣味として続ける中で、いつか自分だけのバラ完車を組みたいと考えていました。
しかし実際に情報収集を始めると、

- フレームとBB規格が合うのか
- ホイールやローターの規格は対応しているのか
- 完成時の重量や総額はいくらになるのか

など、確認すべき情報が非常に多くありました。

結局、メーカーサイト・ショップサイト・ブログ・YouTube・SNSを何度も行き来しながらExcelで管理することになり、「もっと簡単に全体を把握できる方法はないのか」と感じました。

---

### 2-2. なぜそれが「気になった」のか

私は何かを購入する前に比較検討することが好きで、納得した上で意思決定したいタイプです。
また、ロードバイクは高額な趣味であり、パーツ選びの失敗が大きな損失につながります。

そのため、
「完成してから失敗に気づく」
のではなく、
「購入前に判断材料を揃えたい」
という価値観が強くありました。

しかし、その判断を支援してくれるサービスが見当たらず、不便さを強く感じたことが開発のきっかけです。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

バラ完に必要な情報が複数のサイトに散らばっており、価格・重量をまとめて確認できない。

---

### 3-2. 本当に解決したい課題は何か

なぜ困るのか？
→ パーツ同士が適合するか分からない。

なぜそれが困るのか？
→ 購入後に組み合わせられない可能性がある。

なぜそれが困るのか？
→ 高額な買い物で失敗する不安が大きく、理想のバイク作りに踏み出せない。

→ 本当に解決したい課題：
「ユーザーが失敗への不安なく、自信を持って理想のロードバイクを設計・購入できる状態を作ること」

## 10. 技術スタック（手段としての技術）

### 10-1. 使用技術

- フロントエンド：React、TypeScript、Vite、Tailwind CSS
- バックエンド：Hono、TypeScript、Zod
- データベース：Cloudflare D1
- 実行・配信環境：Cloudflare Workers、Workers Static Assets
- テスト：Vitest
- UI：Base UI、ReUI、dnd-kit

---

### 10-2. 技術選定の理由

- ReactとHonoをTypeScriptで統一し、フロントエンドとAPIの型を追いやすくする
- Hono APIとReact SPAを同一Workerから配信し、CORSを必要としない構成にする
- D1とWorkersを利用し、小規模なMVPを低コストで運用する
- ZodでAPI入力値を実行時にも検証する
- パーツ適合判定を純粋なTypeScript関数として分離し、テストしやすくする

---

### 10-3. 今後の技術的な懸念

- ログイン機能追加時の認証・認可とユーザー別データ管理
- D1の制限を考慮したクエリとマイグレーション設計
- パーツデータと価格更新日の継続的なメンテナンス
- 規格情報が不足しているパーツの適合判定方針
- フロントエンドのバンドルサイズと初期表示速度
